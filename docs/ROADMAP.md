# NEXUS LAB 路线图：十个学院，同等重要

## 排序原则

十个学院拥有同等导航可见性、视觉层级和共享学习能力；没有主学院、次学院或中心学院。开源 M01 是历史上的首个学习引擎实现样例，实施顺序不是产品排名。后续交付按学习者需求、前置依赖、可访问性、内容审查、验证成本和资源安排，不自动优先继续扩展开源课程。

同等重要不等于编造十套完整课程，也不要求一次性完成全部内容。每轮计划公开各学院的可用/开发中/规划状态、选择下一切片的依据与未覆盖方向，防止“已有实现”成为永久优先理由。共享基础设施的收益归全部学院。

## Phase 5 — Ten Academy Curriculum Foundation

以 GitHub Issue #1 为准；5A–5D 已实现并进入分支审查。十学院各有一个可用入门模块，详情见 [课程清单](CONTENT_INVENTORY.md)。原 Explorer 作为后续跨学院工具保留。以下 A–D 描述交付要求；实际验证与边界以 CURRENT_STATUS 为准。

## 实施顺序与验收

### A. 学院中立的目录、状态与入口（UI V2 已实现）

统一十学院的导航深度、卡片层级与课程状态展示；首次引导覆盖全部方向且可跳过；首页根据真实目标/最近学习记录续学，提供同级学院入口，不固定导向开源。将内容发布状态与学习者完成状态拆开，替代学院级布尔值承担课程状态的做法。

验收：十个现有学院 ID 与入口保留；键盘/移动端可访问；规划课程不显示虚假可学按钮；部分实验可用不被宣传为学院课程已完成；空记录默认不固定推荐开源。所有旧课程与数据继续可用。

### B. 共享注册表与课程依赖图（Phase 5B 已实现）

按 ARCHITECTURE v2 建立通用课程/模块/课时/测评/作品契约和稳定引用。Git、GitHub、Python、API、云部署注册为共享主题；只对实际已发布内容声明可学习。先用适配器接入现有样例，不为凑目录制造新课程或复制内容。

验收：至少两条不同学院的路径引用同一权威学习节点；检测循环、悬空引用与版本不兼容；必需/推荐/相关依赖行为可解释。已有六课、实验和样例的身份及访问方式不变。

### C. 通用渲染、进度、测评与作品支持（Phase 5C 已实现）

UI V2 已提供同级学院概览/课程状态与共享实践入口、保留状态的课时/实验面板、原有证据的作品详情和本机导出；这不等于完成下述通用课程图和服务器迁移。

让所有学院通过同一查询/渲染接口使用引擎；将课时专用互动改成可注册块；服务端校验、Mentor 与回退使用共同注册表。以兼容、幂等迁移接入旧本机/服务器数据，逐步按共享证据聚合课程与路径进度，并为各学院提供相同项目模板/量规能力。

验收：共享课时不重复计数，路径独有项目分别验收；旧进度/工作表/实验成果、同步和旧链接回归通过；无上下文帮助不默认返回开源内容。尚未实现云作品同步时保持明确标注。

### D. 按同一量规逐步补齐十学院学习切片（Phase 5D 首批已实现）

从下表确定实际下一批内容，使用相同课程模板与“目标→讲解→演示→练习→测评→证据”验收。下表保留方向示例；首批已发布的实际课程及未覆盖内容以 CONTENT_INVENTORY 为准，不将整个方向标成已完成。

| 学院           | 可规划的初学者切片   | 可复用主题/能力示例               |
| -------------- | -------------------- | --------------------------------- |
| 编程           | 变量、控制流与小工具 | Python、Git、共同测评             |
| 人工智能       | 提示设计与结果评估   | Python、API、共同证据             |
| 游戏开发       | 游戏规则与交互原型   | Git、发布、共同项目量规           |
| 计算机工程     | 逻辑门与数字系统     | 逻辑模拟、共同实验框架            |
| 网站与云端     | 网页、请求与部署     | API、Git、云部署                  |
| 网络与安全     | 网络基础与权限判断   | API、安全数据处理                 |
| 机器人与物联网 | 传感数据与控制思路   | Python、API、设备替代方式         |
| 未来科技       | 技术原理与证据辨析   | 共同课时/测评；不强制套用编程先修 |
| 效率与自动化   | 预算公式与流程任务   | 公式引擎、API、共同作品证据       |
| 开源学院       | 授权、社区与协作实践 | Git、GitHub、共同课程引擎         |

每轮交付说明需求依据与依赖，不以“开源已有六课”为理由继续挤占其他学院的学习路径。可用内容数量可以不同，入口地位和共享能力不能不同。

## 可独立推进的工作

账号与隐私加固、跨学院项目保存/导出、可访问性和部署运行验证是共享能力。GitHub Explorer 是多个路径可引用的可选工具，不是平台中心；Google OAuth 等集成保留明确权限和同意要求。实时 AI 的凭据/计费验证是独立阻塞项，不阻塞基础课程或平等学院架构。

## 每轮完成条件

明确列出实际可学内容、仅规划内容和外部阻塞；更新 CURRENT_STATUS；运行适用的 typecheck、lint、tests、build 和浏览器回归；文档设计不得被记录为功能实现。课程状态、学习者证据和外部服务验证分别报告。变更在开发分支形成可审阅提交，不覆盖稳定分支或删除历史学习数据。
